# Pipeline reference

## Work directory layout (created by `scripts/new-video.mjs`)
```
video.json            per-video config (format, scenes/beats, sections, description, YouTube metadata) — see below
brief/                brief.md, storyboard.md, accuracy-notes.md, deck.html (copy of the source deck),
                      scene-guide.md, script-format.md, series-standards.md (copies of the skill's reference docs)
script/script.json    narration (reference/script-format.md)
build/                engine: config, tts, words, captions, music, mix, package, validate-script; data.mjs (yours)
data/numbers.md       illustrative numbers the script may quote (generated by build/data.mjs)
stage/                index.html, runtime.js, tokens.css (engine); scenes/<id>.js (yours); thumbnail.html (yours);
                      generated: video.js, timeline.js, words.js, datasets.js
tools/                still, sweep, render, word-probe, anchor-audit, asr-check, thumbnail, yt (YouTube Studio over CDP)
audio/  out/          generated (lines cache, narration, music, mixes; video, captions, thumbnail, description, QA images)
node_modules -> ~/.cache/ddia-video/node_modules
```
`node scripts/new-video.mjs --dir <work> --update-engine` refreshes engine files (build/, tools/, stage runtime, fonts) without touching
your scenes, script, data or config.

## Commands (run in the work dir)
| step | command | output |
|---|---|---|
| data | `node build/data.mjs` | `data/numbers.md`, `stage/datasets.js` |
| validate script | `node build/validate-script.mjs` | per-scene word counts, runtime estimate, errors |
| narration | `node build/tts.mjs` | `audio/lines/*.wav` (cached by text+voice+speed), `audio/narration.wav`, `build/timeline.json`, `stage/timeline.js`, `stage/video.js` (re-run after editing `video.json` sections/deck) |
| word timings | `node build/words.mjs` | `build/words.json`, `stage/words.js` (whisper; rerun after every tts) |
| narration QA | `node tools/asr-check.mjs` | WER per line (> 12 % flagged; "look-up" vs "lookup"-style hits are false positives) |
| scene QA | `node tools/still.mjs <scene> --qa [--at cue+0.3]` | `out/qa/<scene>/*.png`, `sheet.png`, layout warnings |
| anchors | `node tools/word-probe.mjs <scene> [line needle]`, `node tools/anchor-audit.mjs` | anchor times; audit of every `k.word` (aim: all exact, no fallback) |
| whole-video QA | `node tools/sweep.mjs [--every 4]` | `out/qa/_sweep/sheet-NN.png`, all layout warnings + JS errors |
| render | `node tools/render.mjs --workers 8` | `out/video.mp4` (60 fps, CRF 16; 14 min of long-form ≈ 5 min, a Short ≈ 30 s) |
| captions | `node build/captions.mjs` | `out/captions.en.srt/.vtt` (≤ 2 lines × 42 / 32 chars) |
| music | `node build/music.mjs` | `audio/music.wav` (procedural pad, original) |
| mix + mux | `node build/mix.mjs` | `out/final.mp4` (−14 LUFS, AAC 192k, English mov_text track) |
| thumbnail | `node tools/thumbnail.mjs` | `out/thumbnail.png/.jpg` from `stage/thumbnail.html` |
| package | `node build/package.mjs` | `out/youtube-description.txt`, `out/youtube-meta.json`, `out/script-with-timings.md` |

Re-run order after a script change: `tts → words → (re-anchor scenes) → still/sweep/anchor-audit → render → captions → music → mix → package`.
TTS is cached per line, so only changed lines are re-synthesized; their timings shift everything after them, which is why scenes must
anchor to cues and words, never to absolute seconds.

## Timing model
Scene start = previous scene end. First line starts after `leadFirst` (long 1.0 s / short 0.35 s), other scenes after `lead`
(0.6 / 0.35). Lines are separated by `pause` (default 0.35). A scene ends `max(tail, last pause)` after its last line, plus `endHold`
(2.5 / 1.2 s) on the final scene; `tail` defaults to 0.8 / 0.4. A script scene may set `minDur` (seconds) to stay at least that long
(e.g. a divider). Crossfades of 0.5 s are centred on scene boundaries. Long-form fades in from black (0.6 s) and out (1.2 s);
Shorts start on the hook frame and fade out over 0.6 s.

## Deliverables (copy from `out/` when final)
`<deliverables>/` (long-form `~/Movies/DDIA-Session-N-Video/`, Shorts `…/Short/`) ← `final.mp4` renamed
`DDIA-Session-N-<Slug>.mp4` or `DDIA-ChN-Short-<Slug>.mp4` (`<Slug>` = the topic in Title-Case words joined by hyphens, e.g.
`Reliable-Scalable-Maintainable`, `Twitter-Fan-Out`), `captions.en.srt/.vtt`, `thumbnail.jpg/.png`, `youtube-description.txt`,
`script-with-timings.md`, and a short `README.md` (YouTube link, file list, how to rebuild from the work dir, anything pending). The work
dir under `work/<format>/` stays as the rebuildable source; Chapter 1's `README.md` files are the precedent.

## Machine setup
`node scripts/setup.mjs [--prefetch-tts]` (idempotent): checks node ≥ 20, ffmpeg/ffprobe, whisper-cli, Chrome; installs
`~/.cache/ddia-video/node_modules`; downloads the whisper `ggml-base.en.bin` model; optionally pre-fetches the Kokoro model.
On Linux (cloud sessions), `bash scripts/cloud-setup.sh` first installs ffmpeg, fonts, whisper-cli and Chrome for Testing
(`~/.cache/ddia-video/chrome`), then runs `setup.mjs` (reference/cloud.md).
Env overrides: `DDIA_VIDEO_CACHE`, `CHROME_PATH`, `WHISPER_MODEL`, `DDIA_REPO`, `DDIA_VIDEO_HOME` (default `~/Movies`; `<repo>/videos` in
a cloud session), `YT_CDP_PORT`.
