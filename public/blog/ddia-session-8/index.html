Partitioning

When one machine can’t hold the data or the load: split it, and spread the pieces evenly.

Chapter 6. Also called sharding; a partition is a shard in MongoDB, a region in HBase, a tablet in Bigtable, a vnode in Cassandra.

Partition for scale, replicate for safety.

Each record belongs to exactly one partition. Each partition is a small database of its own.

Combined with replication, every node leads some partitions and follows others.

01

Partitioning key-value data

The goal: no hot spots.

Key range or hash?

Key range

Contiguous ranges of keys per partition, like encyclopedia volumes. Range scans are cheap. Risk: sequential keys like timestamps pile into one partition.

Hash of key

A good hash spreads keys evenly. Range queries now have to ask every partition.

Compound key

Cassandra’s trick: hash the first column, sort by the rest. One user’s posts by time stay together.

Bigtable, HBase, and MongoDB before 2.4 use key ranges; Cassandra, Voldemort, and MongoDB’s hashed sharding use hashes. The hash doesn’t need to be cryptographic, but it must be stable across processes — Java’s Object.hashCode is not.

Lab: where does the load go?

Hash partitioning can’t fix a single hot key. The workaround of adding a random suffix to a known hot key spreads writes but makes reads gather from all sub-keys, and you have to track which keys are split.

Secondary indexes

Indexes don’t partition neatly.

03

Rebalancing and routing

Moving partitions without moving everything.

Lab: never use hash mod N.

of keys move with hash mod N
move with a fixed number of partitions

Fixed partitions

Create many more partitions than nodes (say 1,000 for 10 nodes). New nodes steal whole partitions.

Dynamic

Split a partition when it grows too big (HBase: 10 GB), merge when it shrinks.

Per node

A fixed number of partitions per node (Cassandra), split when a node joins.

With mod N, adding one node moves almost every key. Rebalancing should be supervised by a human: automatic rebalancing plus automatic failure detection can cascade — an overloaded node is declared dead, its load moves to others, which become overloaded too.

Which node has key “merchant:7”?

Someone must know the current assignment: ZooKeeper (HBase, Kafka, SolrCloud) or a gossip protocol (Cassandra, Riak).

This is an instance of service discovery. Analytic MPP databases go further and split one complex query into stages across partitions.
